About Release Orbit

An independent tracker for operating system releases: when each release and beta landed, which build it is, and what came in between. Apple comes first.

What this is

Release Orbit answers one question quickly: what is the newest version of each platform, and how recent is it? It is built to follow more than one vendor, and Apple is the first. For Apple that means iOS, iPadOS, macOS, watchOS, tvOS and visionOS. The front page shows the newest release or beta of each family with its build number and date, and every family has its own section below with its recent releases.

The timeline lists every release in the data, newest first and grouped by month, and you can filter it by platform and by stage. The compare page takes one platform and two of its releases and shows both builds and dates, the calendar days between them, how many betas and release candidates were published in between, and the list of everything in between. Every entry links to the source page for that release.

Where the data comes from

Release data comes from Apple Developer Releases, developer.apple.com/news/releases (opens in a new tab). A small Cloudflare Worker reads Apple's feed, keeps the six OS families and drops everything else (Xcode, App Store Connect and so on), turns the publication times into UTC, and serves the result as JSON at /api/releases.json. Adding ?vendor=apple asks for one vendor only.

Each vendor is its own source with its own cache and its own fallback, so one source failing never blanks another. Only the title, build, date and link of each release are kept; no release notes are copied. The feed holds only Apple's most recent items, so the Worker merges what it reads with a saved snapshot that ships with the site. That is how older releases stay on the timeline. When a source cannot be reached, the Worker serves the last copy it has, and the front page says so: the status line reads Live when the data was just fetched, Stale when a source was unreachable and an older copy is shown, and Saved copy when the page is showing the snapshot that ships with the site, as it does in a local preview.

The developer highlights on the front page are short summaries written for this site. Each one links to the vendor page it refers to.

How often it updates

The Worker keeps a fetched copy for ten minutes. An open page asks the Worker again every five minutes while the tab is visible, and stops asking while it is in the background. When a release appears that the page has not shown before, a short notice announces it. The snapshot that ships with the site is refreshed by hand and committed, so it can lag the live data by days; it only matters when the live data is unavailable.

A release is published first and the feed picks it up afterwards, so it can show up here some minutes after it is announced. The dates and times shown are the feed's publication times in UTC.

Reading the labels

A Release is a public version. A Beta is a developer or public beta, numbered the way the vendor numbers it: beta 3 follows beta 2. An RC is a release candidate, the build intended to ship unless something is found. Where an RC is not numbered, the label is just RC.

A build is the short code after the version, such as 24B5099f. Two releases of different platforms can share a version number and still be different builds, and a platform can have several releases on one day. On the compare page, "in between" means every release of the same platform listed between your two picks, newest first, and the days between are calendar days in UTC.

Validation results

The project also has a place for validation results: for a build, a short list of checks and an overall status of pass, warn, fail or untested. Only builds that are publicly released get published results. Pre-release software results stay private until the build is publicly released. No results are published yet; when they are, they are tied to the build number shown here.

The device screens

The iPhone, iPad, Mac, Apple Watch, Apple TV and Vision Pro on the front page are drawings made for this site in CSS. They are not Apple's artwork or product photos, and the screens on them are mock-ups that show the newest release in the data. The Software Update check on the iPhone, the About This Mac window and the watch complication are interactive, and they only read the same data as the rest of the page: nothing is installed or checked on your device.

Privacy

There are no accounts, no cookies, no analytics and no third-party scripts. The page remembers one thing in your browser, your theme choice (day, night or the console theme), and only on your device. The page requests release data from this site only; web fonts are the one request that goes to another host, Google Fonts. Links to a release open the vendor's own page in a new tab.

Accessibility

Every control is at least 44 pixels in each direction and reachable with the keyboard, with a visible focus ring. Status changes (a refresh, a filter, a mock Software Update check) are announced politely to screen readers. Colours in every theme are chosen to meet WCAG AA contrast, and nothing relies on colour alone: stages are written out as words. The scroll reveals, the background drift and the lift on a card move only transform and opacity, and all motion stops when your system asks for reduced motion. Pages show their content before any script runs, and the release lists link to the source when JavaScript is off.
